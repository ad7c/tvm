## Exp-2：双向剪枝核心对比

### 设计

三种模式，同一算子，同一种子序列（但 C++ 随机性不可控，取 3 次平均）：

| 模式 | 硬约束 | 软惩罚 | 预期耗时比 |
|------|--------|--------|-----------|
| Baseline | 无 | 无 | 1× |
| Upward | shmem + threads + vk≠1 | 无 | ~0.3× |
| Upward+Downward | 同上 | occupancy + reuse | ~0.2× |

### 指标

| 指标 | 含义 |
|------|------|
| 找到 3 个合法的耗时 | 墙钟时间 |
| TVM postproc 调用次数 | 省了多少次沉重检查 |
| 预检通过率 | 硬约束砍掉多少 |
| 第一个合法在哪一步 | 搜索收敛速度 |
| 合法候选性能分布 | 软约束是否丢了好配置 |

### 算子矩阵

| 算子 | 规模 | 硬约束公式 |
|------|------|-----------|
| MatMul | 128³, 256³, 512³ | `(bi·bk + bk·bj)×8 + bi·bj×4` |
| Conv2D | (64,3,7,7) → (64,56,56) | 多维 shmem 估算 |
| Reduction | 256 | 无 shmem，仅 threads |
| Element-wise | 256 | 无约束（过检率 100%） |

**产出**：核心对比表 + 加速比曲线（X 轴 = wall-clock 时间，Y 轴 = 找到的合法/最优候选数）

## Exp-3：消融

### 3a. 硬约束贡献分解

跑 5 组，每次去掉一个硬约束：

| 去掉的约束 | 预期效果 |
|-----------|----------|
| 全量（4 条全开） | 最强剪枝 |
| - shmem | 漏掉 shmem 超限 |
| - threads | 漏掉线程数非法 |
| - vk≠1 | 漏掉 buffer 脱钩 |
| - 全关 | = baseline |

### 3b. 软约束权重调参

固定硬约束，变 α, β（occupancy 权重, reuse 权重），找帕累托最优。

### 3c. 保守性证明

**命题**：硬约束不会排除任何"合法且优于当前最优 10% 以上"的候选。

**验证方法**：在无剪枝的 baseline 中收集 200 个合法候选的性能分布，确认没有任何好候选落在硬约束之外。

## Exp-4：通用性

### 算子覆盖

4 类算子，验证预检框架只需换 `estimate_shmem()` 一个函数：

1. **GEMM**：MatMul 128³/256³/512³
2. **卷积**：Conv2D (3×224×224) → (64×112×112)
3. **归约**：LayerNorm (128,128)
4. **逐元素**：Add + ReLU fused

每个算子：baseline vs upward → 记录有效加速比。

### 规模扩展

MatMul 从 128³ 到 1024³，验证剪枝率随规模的变化趋势。
