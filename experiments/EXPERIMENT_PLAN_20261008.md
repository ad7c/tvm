## 1. 研究问题与目前能说的结论

研究目标不是让某个指标看起来更好，而是回答：**在不误拒基线可行候选的前提下，
能否以更少调优资源找到同样好或更好的程序？**

拆成四个可分别验证的问题：

1. 安全性：提前拒绝是否有依据，是否误拒可行/高性能候选？
2. 候选效率：得到相同数量有效候选，需要生成、replay、lowering 多少次？花多久？
3. 搜索效果：同提交测量预算、同调优时间下，找到的 kernel 是否更快？
4. 归因与通用性：收益来自 CS、H 的前移位置还是 Draft 选择；能否跨算子/shape 复现？

目前最强证据是候选效率，不是稳定的端到端加速。Draft-GA 的调用位置已验证，
但原始 Draft 排序不能保证质量。双信号选择仍是假设，不能预写成论文成果。

## 3. 怎么比才既公平，又能检验我们的优势

| 比较问题 | 控制条件 | 主指标 | 解释边界 |
|---|---|---|---|
| 更少无效工作？ | 相同有效初始化返回配额 | attempts/unique-valid、replay/lowering次数、凑齐配额时间 | 少候选不等于少时间 |
| 前移真的省时间？ | 同一冻结trace池、相同原始决策 | 每层耗时、拦截位置、剩余验证成本 | 不混入CS改变采样分布的效应 |
| 同测量预算选得更好？ | 相同提交给Builder的次数、batch、训练条件 | best-so-far、finite比例、最终重测延迟 | build失败仍占预算，不能悄悄补测 |
| 同成功测量数怎么样？ | 固定finite配额作为补充口径 | best、补测次数、全部补测成本 | 必须同时报告提交总量与墙钟 |
| 更早达到目标？ | 预先固定每workload的目标和截止时间 | time/trials-to-target、成功率 | 未达标记右删失，不能只平均成功者 |
| 同真实时间选得更好？ | 相同tune墙钟截止点 | 截止前可用的best、GPU实测数 | 不能计入截止后才完成的batch |

同seed并不产生同一候选列表：CS改变了决策和随机数消耗。同seed配对用于统计控制；
固定trace池用于机制归因，两者不能互相替代。

主指标用相同**提交测量预算**及完整tune墙钟；finite曲线作为辅助。
当前两组没有build失败，因此submitted与finite相同，历史M32b则不同。
算法性编译/测量失败保留在正式固定提交预算结果中；外部中断、没有完整产物的运行另列
诊断。不能不断重跑直到全finite，再只发表成功运行。

### 3.1 达标口径

历史pilot允许采用“同seed B最终值”为描述性参照，同时报告0%、1%、2%、5%阈值，
不据此认定稳定优势。正式评估先用独立参考运行确定 `L_ref(workload)` 并冻结，
报告 `L <= (1+epsilon)*L_ref`；预注册主阈值2%，1%/5%作敏感性分析。
参考运行成本单列。不得看完测试结果后选择最有利阈值。
`L_ref`由独立参考候选的重复测量中位数确定，不使用一次噪声最小值。

现有batch时间只支持批末阶梯曲线，不插值得出批内精确到达时刻，不从第0秒画出尚未测得的best。
双方都取**第一次**达到同一阈值的位置。没有达标的run保留在分母中；
可以报告共同截止前的达标率或限制平均达标时间，不把未达标当作0秒，也不只平均达标者。
固定submitted用尽而提前终止的run，应报告“该预算策略未达标”，不能假装它一直搜索到T。
只有真正具有共同观察期限的墙钟实验才汇总截尾的时间统计；小样本优先展示每seed结果和
未达标标记，不把截止时间填入普通成功者均值，也不将失败run从分母移除。

### 3.2 统计与噪声

- 开发至少3个配对seed，冻结方案后正式目标5个新seed；报告全部配对点与均值/中位数。
- 算子内计算延迟比和时间比；跨算子汇总用几何平均，不直接平均不同shape的μs。
- 3个seed不足以稳健显著性论证；5个seed仍需显示散点及区间，不只放均值柱。
- 对最终选中的top-1（必要时top-3）独立重复GPU测量，固定warmup/repeat，报告中位数与波动；
  重测预算每臂相同，单列成本，不回流选择，以减少“取最小值”偏差。
- 同GPU串行运行，交错/随机化B/C/D/Q顺序，记录GPU实际型号、驱动、时钟/温度、后台负载。
  Draft硬件profile名称不是实机型号证据。

### 3.3 哪些比较最能解释优势，哪些不能替代总收益

- CS主要用“相同有效候选配额”检验生成效率，同时报告去重率、抽样分布与花费，
  不以更少attempts代替更好kernel。
- H用“同一完整trace池”检验提前拒绝带来的净收益：
  `净节省 = baseline完整路径时间 - H检查加幸存者完整路径时间`。
  检查、计划构造、必要的回放全部计时；采集成本另外报告。
- Draft用“同一候选池、同一K、同一标签预算”检验选择质量，再用在线等提交预算/等墙钟
  验证搜索效果；只减少XGB调用次数不是质量或时间的充分证据。
- 当前B的search约63–72秒，builder约350–359秒，tune约506–530秒。
  在其他阶段不变的反事实下，就算消除整个search，总时间也只减少约12%–14%；
  这解释了为何局部剪枝很大、总时间收益却有限，不是优化理论上限的普遍结论。
  要产生更大总收益，更有价值的目标是**减少达到目标所需的昂贵编译/测量次数**。
- 搜索组件固定CPU时间/固定有效候选的结果可作为机制证据；主结论仍使用含builder、
  runner、XGB更新的完整tune时间。setup另列，并同时给出setup+tune的用户可感知总时长。

### 3.4 如何突出优势而不改变比较口径

主结果用“两轴”而非一个有利的汇总百分比：同提交预算的最终kernel延迟比，以及完整
tune时间比；均以B为1，全部shape/seed显示。左下象限才是时间与质量同时改善；
一项更好、另一项更差就报告权衡，不单用计数包装成系统加速。

- CS/H的首要机制图：固定有效配额的生成数/耗时，以及固定池同候选的实际净成本。
- Draft的首要效果图：达到同一目标需要多少次昂贵Builder/GPU提交、多少完整tune时间。

### P2：Draft新选择机制的可行性（先离线，再上GPU）

先检查是否有完整的候选归档、真实parent-child对应关系、parent和child原始Draft分数。
历史最终tuning记录只保存已选择候选，不能还原全部未测候选和谱系。
缺失就做小规模shadow采集，不能按tile相似度捏造父子关系。

验证假设：

`DeltaDraft = log((D(child)+eps)/(D(parent)+eps))`。

只对known、同定义、可比的原始正分数使用；不能对每代独立归一化后分数做比值。
Delta不是新实测信息，也可能继承Draft偏差。必须先检验其与真实
`log(latency(parent)/latency(child))` 的相关性、改进符号一致率和置信区间。
unknown进入探索，不能以低分当合法性硬拒。

离线对照：随机合法选择 / absolute-only / absolute+diversity /
absolute+Delta / absolute+Delta+diversity（之后才加slack以免一次改变太多）。
固定池和K，输出Recall@K、best regret、签名覆盖、真实改进命中率、selector成本。
相同parent/template不得跨开发/评估划分泄漏；超参数只在开发集选。
只测已选择样本池时必须称“池内诊断”，不能称无偏全空间Recall。
模板数不足以隔离时，使用独立shape/workload留出，或仅报告父组隔离的池内诊断，
不能把它说成跨模板泛化。

额外必做“相同父组配额+随机子代”和“相同父组配额+子代绝对Draft排名”两个对照。
对同一父代p，`Delta(p,c)=log(D(c)+eps)-log(D(p)+eps)`的第二项为常数，
因此组内Delta排序与子代absolute排序相同（同分采用相同tie-break）。固定父组配额时，
不能把完全相同的入选集合叫新增方向信息。先不跑GPU就比较入选id/集合重合率；
若恒等，停止这个实现分支，保留“父组均衡”的真实解释。
只有明确的跨父组比较或配额分配改变了选择，才继续检验Delta；这时还需控制弱父代
天然更易取得大相对增益的偏差，不能把“进步大”等同“最终快”。
所有selector共享池、K和随机探索名额；保存实际入选id，
区分“选到不同候选”与“换了名字但集合完全一样”。

首轮可行性标签预算建议：每个workload固定8个合法父代、每父代4次单子代提案，
最多32个子代；父子去重后的所有oracle通过者均测，不按Draft预选标签。
每workload至多40个独立程序的builder/runner提交，先MatMul128和语义验证后的Conv2D，
共至多80个；重复测量的次数/耗时另记。失败提案不悄悄补抽；合法子代不足K则记录不足。
先看K=4/8的池内诊断，不在这两个小池上宣称统计显著或跨算子泛化。
若信号有用，再另采开发/验证池，按父组/template隔离后调参及独立评估。

绝对精英、父组Delta配额、随机探索配额之和固定为K；保留多样性基线以判断收益是否只是
随机探索，而非Delta。每次变异只产一个子代计算比较，首版不多分支试探，不增加完整replay。

进入在线的条件：测试池中未见明显系统退化、新增信号优于随机/简单多样性、
谱系与成本可核对。若无增益，不继续堆G1/G4；把失败写清楚并保留C主线。
通过后单seed16-trial shadow/enforce，再三seed；始终验证GA内XGB=0。
