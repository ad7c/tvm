# 实验评估方案与后续任务

## 1. 已确认的安排

实验写作主线为：**整体效果 → 搜索过程 → 组件贡献 → 成本与排序原因**。

参考本地 [Pruner 论文](<Pruner_ A Draft-then-Verify Exploration Mechanism to Accelerate Tensor Program Tuning.pdf>) 第 5、6 节的组织与指标，使用本项目的模型、设备和方法配置，不照搬其数值结论。

### 1.1 预算与对照

| 项目 | 最后确认的安排 |
|---|---|
| 模型级调优 | 每个模型、每种搜索配置共 2000 次 trials；最多 200 轮调优，每轮提交 10 个候选，预算在模型提取的任务间分配 |
| 单算子调优 | 每个算子、每种搜索配置 800 次 trials |
| GA 代数 | 与硬件实测预算分开说明；保留已有 GA1/GA4 的评分开销对照，正式长预算运行参数开跑前统一冻结 |
| 搜索配置 | B：Baseline（原 MetaSchedule）；C：CS+H；D：CS+H+Draft-GA（完整方法） |
| 外部参考 | 增加 PyTorch 推理性能；不把 PyTorch 画成有搜索过程的调优方法 |
| 搜索 seed | 暂用一个固定 seed；沿用 20261011，不新增多 seed 比较任务 |
| 模型 | ResNet-18 为主；补一个小型 LLM，具体名称待定 |
| 设备 | 现有 RTX 3050 Ti Laptop GPU；补第二块 GPU，具体型号待定 |

**预算口径纠正：**讨论中曾将“2000轮”解释为 GA 迭代 2000 代。阅读 Pruner 后，用户最终选择“采用 Pruner 预算”：模型实验 2000 次候选实测、算子实验 800 次。该选择覆盖先前的 GA 2000 代说法，不能按 GA 2000 代启动实验。

Pruner 的 200 轮指调优反馈轮次，与 GA 内部进化代数不同；其 2000 trials 是模型级总预算，不是每个子算子各 2000 次。本项目继续采用失败提交占预算、不补录失败次数的规则，并报告实际提交与成功测量数量。后者是本项目的执行约定，不声称 Pruner 原文明确规定了相同失败计数方式。

### 1.2 正文取舍

- CS+H 以候选数量说明作用：生成次数、Verify 失败次数、后处理通过次数及通过比例，不在这组图表中附搜索时间。
- Draft 展示 GA1/GA4 的评分节省，重点为绝对预测时间节省由约 2.23 秒增加到约 6.10 秒。
- 现有 32 次提交下的整体性能差异暂不作为正文主结果，保留在附录、结果报告和原始数据中。正式整体效果等待长预算实验补齐。
- 小型 LLM、第二块 GPU 均纳入接下来的实验，正文先预留位置，明确标记待测。
- 未完成的结果不写提升比例、不预设加速结论。短预算下代价模型训练不足可以作为待检验解释，不能直接写成已验证原因。
- 本轮不安排官方 Pruner 完整复现、离线大数据集预训练或跨 seed 显著性分析。Pruner 的 PaCM、MoA 不属于本项目已实现组件。

## 2. 已完成实验与可复用数据

当前正式算子批次使用一个搜索 seed、每臂 32 次提交、批大小 4、种群 32。MatMul128 分别运行 GA1/GA4，MatMul256、标准 Conv2D、大 Reduction 使用 GA1，全部比较 B/C/D。

共 15 次正式运行、480 次提交，全部取得有限且数值正确的测量。15 个原最佳候选已独立重建，每个取得 30 个计时样本，共 450 个技术样本；这些样本不是额外搜索 seed。

## 3. 论文实验部分的组织

### 3.1 实验设置

统一列出设备、软件版本、模型与算子形状、精度、预算、搜索超参数、代价模型、seed 和计时范围。区分已有 32 次提交的初步批次与待完成的 800/2000 trials 正式批次，不将旧数据改名为长预算结果。

ResNet-18 的起始设置沿用 batch=1、输入 1×3×224×224、FP32。模型权重和输入固定；所有方法保持同一图优化与精度规则。PyTorch 的版本、后端、TF32 设置及计时范围应在正式运行前记录。LLM 名称、输入长度、精度，以及第二块 GPU 的具体配置先保留待定字段。

### 3.2 整体效果

先回答最终获得的程序是否改善推理性能。正式模型实验使用 ResNet-18 和小型 LLM，覆盖两块 GPU；单算子使用 MatMul128/256、标准 Conv2D、大 Reduction，预算为 800 trials。

预留总体性能表：设备、模型/算子、输入与精度、B/C/D 和 PyTorch 的独立实测延迟。模型用毫秒，算子用微秒，避免混合单位。性能柱状图固定以 B 为基准，定义加速比为 L_B/L_method，并同时保留绝对延迟。

LLM 优先预留 prefill/固定输入前向性能；若后续开展 decode，另列每 token 延迟、KV cache 条件与生成长度，不与 prefill 混为一个结果。

### 3.3 搜索过程

对应 Pruner 图 6，横轴为累计调优墙钟时间，纵轴为模型推理延迟，曲线为 B/C/D。模型按行、GPU 按列安排面板；PyTorch 只作为固定性能参考，不画成搜索轨迹。

对应 Pruner 图 7、表 9，报告达到 B 完整 2000 trials 搜索终点性能所需的时间。达标加速比定义为 T_B,end/T_method,target。未达到目标标为 NR，并保留运行截止时间。

目标来自基线完整搜索终点，说明其为回顾性基准。曲线只在实际反馈或检查点结果可用时更新，不在批次内部插值。模型检查点若暂用算子延迟加权汇总，必须标为代理曲线；最终性能必须由完整模型实测，不能用代理值冒充端到端延迟。

相同 trials 的最终质量与相同累计时间检查点下的质量分别比较；后者若从长运行中截取，标为时间截点分析，不声称已经执行独立墙钟预算实验。

随后预留统一版本的消融表和收敛曲线，对应 Pruner 表 12、图 16。配置包括 Baseline、仅 CS、仅 H（回放后）、仅 H（分层）、CS+H、仅 Draft、CS+H+Draft。

### 3.5 成本与排序原因

先展示已有 GA1/GA4 的 Draft 评分节省图表。再对应 Pruner 表 7，预留完整调优时间表，并使用互斥阶段拆分 Search、Builder、Runner+notify、Callbacks 和编排剩余时间。

进一步区分实际编译与 Windows worker 启动；模型预测、特征提取与更新属于阶段内细项，不与顶层时间重复相加。

对应 Pruner 表 10/11、图 14，预留候选保留与排序质量分析：在同一固定候选池内，包含入围与未入围候选，比较 Draft、学习代价模型和真实 GPU 延迟。

- Best-1 衡量 Draft 保留集合中最优实测候选相对池内最优的质量。
- Top-k 采用 Pruner 的延迟比指标：各任务池内最优延迟的加权和，除以按预测排序前 k 个候选中最佳实测延迟的加权和；更接近 1 为优。
- Recall@K 是集合覆盖指标，与上述 Top-k 分开命名和报告。
- 入围比例先预留 0.125、0.25、0.50 三档；实际入围数受每批提交数量下限约束，同时报告比例与有效数量。

不为使用同样指标而复制 Pruner 的大规模 TenSet 训练实验，也不将本项目的 Draft 集成写成已经复现其全部系统。

## 5. 下一步任务与执行顺序

1. **先重组论文实验章节。**按上述四条主线修改，放入准确的数量表和评分节省图表；其他正式结果预留待测位置。现有短预算整体结果移入附录。同步校准摘要、引言实验概述、结论，保留已经确认的 3.1、3.2 方法文字与算法。编译并检查双栏图表。
2. **准备 ResNet-18 完整测试闭环。**统一 B/C/D 开关，应用数据库编译完整模型，完成输出正确性、CUDA 同步、预热和独立推理计时；增加同权重、同输入的 PyTorch 参考。旧 ResNet 入口需要 Torch，不能直接沿用排除 Torch 导入的算子专用 bootstrap。
3. **冻结并运行长预算主实验。**算子各 800 trials；ResNet-18 各 2000 trials、每批 10 次。统一 GA、种群、warmup、探索比例、模型更新和任务分配设置；保留失败账本、每批记录与源码/DLL 身份。GPU 测量串行，正式赢家另行独立重测。
4. **生成正式整体与搜索过程图表。**输出最终性能、延迟—时间曲线、达到基线完整搜索终点所需时间、同时间截点比较以及完整成本表；将待测位置替换为可追溯结果。
5. **补组件与排序实验。**完成仅 CS、仅 H、仅 Draft 及 H 位置对照；在独立候选池上做保留比例、排序质量与完整评分成本分析。先复用现有历史实验思路，再统一到正式版本。
6. **扩展小型 LLM 和第二块 GPU。**这两项是已经确定的后续任务。先确定模型与设备、验证导入和显存容量，再补同口径的模型结果；预留位置始终保留，完成后填入。

下一次先做第 1 项，同时准备第 2 项。正式跑数前仍需落实：小型 LLM 名称、第二块 GPU 型号、模型权重来源、长预算搜索超参数与模型任务分配规则。本轮不把多个 seed 设为开跑条件。
