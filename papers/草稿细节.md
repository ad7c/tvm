# 草稿细节（解析评分 Draft 模型）

## 1. 我们用的惩罚项（4 个）

| 惩罚项 | 代码公式 | 含义 |
|---|---|---|
| `warp_penalty` | `block_size/warp_size` 向上取整后的比值 | block 线程数不满一个 warp 时的利用率损失 |
| `peak_penalty` | `scheduling_units / (waves × capacity)` | grid 不满 SM 时分波次跑、最后一波不满的损失 |
| `register_penalty` | `max(register_usage / register_capacity, 1)` | 寄存器超限导致每 SM 可驻留 block 数下降 |
| `thread_reuse_penalty` | `1 + 1 / data_reuse_penalty` | 算术强度低时放大计算时间（补偿访存等待） |

## 2. 代码怎么写的

特征提取（`src/s_tir/meta_schedule/draft_model.cc` 的 `PrunerDraftFeatureExtractor`，遍历 S-TIR）：
`compute_workload`（总 FLOPs）、`dram_workload`（DRAM 流量）、`register_usage`（寄存器代理）、`data_reuse_penalty`（算术强度 FLOPs/byte）、`grid_size`、`block_size`。

打分（`ScorePrunerDraftFeatures`）：

```
compute_throughput = peak_gflops × peak_penalty × warp_penalty / register_penalty
compute_time = compute_workload × thread_reuse_penalty / compute_throughput / 1e6
memory_time  = dram_workload / global_memory_gbps × 1000 / 1024³
total_latency += max(compute_time, memory_time)    // roofline 取瓶颈
score = 1 / total_latency
```

## 3. 和 Pruner 官方 Eq.1 不一样的地方

| | Pruner 官方 | 我们代码 |
|---|---|---|
| 时序组合 | `L_total = Σ(L_c + L_m)`（相加） | `max(compute, memory)`（roofline 取瓶颈） |
| 惩罚数量 | 6 个（L0/L1/L2 × compute/memory） | 4 个（warp/peak/register/reuse） |
| 访存项 | `U_m = T_m · ∏ P_{li,m}`（三层连乘） | `dram/bandwidth`（单层 DRAM） |
| 计算项 | `U_p = T_p · ∏ P_{li,c}`（三层连乘） | `peak × warp / register`（3 项乘除） |

## 4. 优点（相对 Pruner）

1. **max 比相加更物理**：roofline 认为执行时间由"计算/访存"中更紧的一方决定，假设两者可流水线重叠；Pruner 的相加假设完全串行。我们的 max 更贴合 GPU 计算与访存可重叠的事实。
2. **更轻量**：4 惩罚 vs 6 惩罚、单层 DRAM vs 三层连乘，草稿打分更便宜，适合进化循环内高频调用。
3. **诚实标注"代理"**：寄存器/复用是解析估计而非实测，论文参数表已标明"代理"。

## 5. 诚实的局限（待改点）

1. **简化换精度**：把 Pruner 的三层模型简化成单层 DRAM，漏掉 L0/L1 细节，草稿精度有限（实测 Spearman ≈ 0.40）。
2. **`thread_reuse_penalty` 与 `max` 重叠**：`1 + 1/AI` 想补偿"访存等待"，但 roofline 的 max 已经处理了访存瓶颈，两者可能双重计数。
3. **访存侧欠罚**：`dram/bandwidth` 没建模合并访问（coalescing）与延迟，跨步访问的候选被高估——待补 coalescing 因子。
